V2 · Radial Rings · The Premium Take

Rings instead of bars. Premium at-a-glance feel.

Apple Fitness / Activity-inspired. First Wind becomes a pair of concentric rings — outer = Energy Available, inner = Energy Consumed — with a bold center readout. Recovery metrics become three satellite rings (Hydration, Nap, Fasting). Scans faster than V1 and feels like a health-product upgrade. If you want the "wow" version, this is where we'd take it.

What's different from V1

  • No slider, no batteries. Input is a radial ring the user taps/drags around to set their %.
  • Energy Available + Consumed unified into one visual — the two concentric rings.
  • Recovery Snapshot becomes ring satellites (3 small rings in a row) + a compact edit strip below for Nap and Fasting detail access.
  • Center readout is the star — big gradient "80%" + label.

Unity implementation notes

Rings are the main lift. Unity's stock UGUI doesn't draw arcs natively, but there are three solid paths — all proven in mobile Unity apps:

  1. Image with Image.Type = Filled, Radial360. Simplest. A circle Image with fillAmount = 0.0–1.0 and fillMethod = Radial360 gives you a partial ring. Stack two concentric ones for outer/inner. Works out of the box with UGUI.
  2. Custom shader (the OuterRoundedFillFixed.shader already exists in Assets/Custom Shader/). If the designers want rounded caps and glow, this is the route.
  3. Procedural mesh — overkill for this. Skip.
Recommendation: go with option 1 (Radial360 Image) for the MVP. If you want the polished rounded-cap/glow look, we'd escalate to the custom shader in a follow-up ticket.

Tap-to-adjust on the ring requires a PointerEventHandler on the ring's RectTransform that maps tap angle → %. Slightly more code than a Unity Slider, but not complex.

Files to touch (same as V1, plus shader work)

  • Assets/My Scripts/CheckInsPanel.cs — replace slider/batteries block with ring.
  • Assets/My Scripts/LoadoutEnergyBar.cs — repurpose to drive fillAmount on the ring Image instead of colorizing batteries.
  • Assets/My Scripts/DataConfig.cs — same model change as V1 (enum → numeric).
  • New: EnergyRingHandler.cs — handles tap-angle → % mapping for ring input.
  • Assets/Custom Shader/ — consult existing OuterRoundedFillFixed.shader if polish is needed.

V3 · Segmented Picker · The Pragmatist

No slider. Five taps. Shortest path to ship.

Instead of a slider, the user picks one of 5 discrete levels — 0%, 25%, 50%, 75%, 100% — each shown as a tap-to-select battery cell. The selected cell gets a green glow. V3 is deliberately the least-ambitious visual, because its win is implementation speed — it keeps the existing "enum" data model (low/medium/high), just expanded to 5 values, so the backend coordination dependency disappears.

What's different from V1

  • No slider. Input is 5 tap-to-select cells — same mental model as the current 3-state battery picker, just with 5 levels instead of 3.
  • 80% becomes 75%. With discrete levels, the input snaps. Users can't express "80%" — only 75% or 100%. That's the honest tradeoff: less granularity, more clarity.
  • Readout pill shows the selected % + a qualitative label ("Strong day", "Solid", "Empty tank", etc. — copy TBD).

Why this is the easiest ship

No backend coordination needed. firstWindValue stays an enum. Just change the allowed values from "low"|"medium"|"high" to "0"|"25"|"50"|"75"|"100" (or keep named constants — whatever's clean). This means V3 can ship on Unity side with zero backend ticket.

Implementation is a near-direct reuse of the existing battery-array pattern:

  • Existing pattern: HabbitPanel.Instance.firstWind[] is a 3-Image array; tapping one updates DataConfig.userTodaySurvey.firstWindValue.
  • V3 pattern: same, but a 5-element array + the "selected" visual state (green border + glow).
  • Nothing new to import. No slider logic. No ring math. No tap-angle math.
