What changes vs your current in-app Checkin Screen

Today, your First Wind input is a 3-state battery picker ("low" / "medium" / "high") on the HabbitPanel.firstWind[] Image array, set via LoadoutEnergyBar.SetFirstWindData(). Recovery information shows hydration as a row + segmented bars and Deep Breathing/Soundscape as edit rows inside one card.

What you'll see in the new direction:

  • First Wind input becomes a continuous slider (0–100%) with the 4 battery icons as a visual reference for what each level looks like. V1
  • Energy Consumed visual bar (display-only, not yet wired) sits below a divider in the same card. V1
  • Recovery Snapshot becomes 3 satellite mini-rings (Hydration, Deep Breathing Mins, Soundscape Minutes) above a compact card with just Deep Breathing + Soundscape edit rows. Hydration loses its segmented bars and "1.5 liters" caption — it now shows only as a ring fill (e.g. 3/4). V2
  • Centered card heading + gradient % readout on the First Wind card — visual polish carried in from V2. V2
Backend dependency you should know about. Survey.firstWindValue and Survey.secondWindValue in GameManager.cs are currently string ("low"/"medium"/"high"). To ship the slider, they need to accept a numeric percentage (0–100). We'd have Abdul coordinate with your API owner before implementation lands.

Annotated walkthrough

1
First Wind card — centered header + subtitle V2 polish
UGUI TMP_Text with alignment = Center. Header "First Wind Energy", subtitle "How did you use your peak energy today?". Lives on the existing First Wind card inside the Checkin Screen prefab (owning panel: CheckInsPanel.cs).
2
Battery row (4 visual states) V1
HabbitPanel.firstWind[] is currently a 3-Image array. Extend to 4 elements matching the slider ranges (red 0–25, amber 26–50, yellow 51–75, green 76–100). Drive colors via the slider's OnValueChanged rather than user click — batteries become a reflection of the slider.
3
Slider + % readout (primary input) V1
Built-in Unity UnityEngine.UI.Slider, range 0–100, no whole-number snap. Bind onValueChanged to (a) update the battery row tint and (b) write to DataConfig.userTodaySurvey.firstWindValue (after the model change). The "80%" readout is a TMP_Text with the gradient color treatment.
4
Energy Consumed bar (visual only) V1
Build the visual exactly as shown, hardcode 80%. Per the original ticket scope: don't wire the logic in this pass. Image with Type = Filled, Fill Method = Horizontal, Fill Origin = Left.
5
Second Wind expand row (collapsed) V1
Tapping expands into the same First Wind layout (slider + battery row). Use the existing PopupAndDownAnimator.cs pattern — DOTween DOScale(Vector3.one, 0.5f).SetEase(Ease.OutBack) on enable. Backing field: DataConfig.userTodaySurvey.secondWindValue.
6
Recovery Snapshot — 3 satellite mini-rings V2
Three Image elements with Type = Filled, Fill Method = Radial360, Fill Origin = Top. Drive image.fillAmount from data: Hydration = DataConfig.userTodaySurvey.hydrationValue / 4f, Deep Breathing = cycles completed today × pattern duration ÷ daily target (read from BreathworkPanel), Soundscape = DataConfig.userTodaySurvey.fastingValue / hoursTarget as visual placeholder until the soundscape data path is wired. Animate with image.DOFillAmount(target, 0.5f).SetEase(Ease.OutCubic). The custom OuterRoundedFillFixed.shader in Assets/Custom Shader/ is the upgrade path if rounded caps / glow are wanted.
7
Deep Breathing row V2
"Open Deep Breathing →" button (deferred style, matches Soundscape) routes into the existing BreathworkPanel flow — the same module that's now wrapped up at prototypes/breathing-module/ (live · spec SPEC_breathing.md / AJE-65). Logging is not a manual time entry; minutes are tracked from completed cycles inside the breathing module. The satellite ring above this row reads back the day's cycle total when CheckInsPanel.OnEnable fires, then animates to fill via image.DOFillAmount. The 5-cycle XP refund you called out is the gate-deduct-and-refund flow detailed in SPEC_breathing.md "XP economics" — it crosses AJE-11 (Max 75% discount) and AJE-12 (the gate popup that deducts XP).
8
Soundscape edit row V2
Edit button → FastingPopup.Show() + FastingPopup.Instance.EnableBGOpacity(). Subtitle copy: "14h · 8:00 PM → 10:00 AM" (V2 wording — replaces V1's "14h from 8:00 PM to 10:00 AM"). Fasting icon uses --accent-purple instead of blue.
9
Success banner V1
Shown when thresholds hit. Suggested defaults — happy to pressure-test these with you: First Wind ≥ 60%, Hydration ≥ 3/4, Soundscape minutes hit target.
10
FINISH button V1
Existing handler: CheckInsPanel.MarkTodaysStatusComplete() → NetworkAPImanager.IsTodaysStatusBtnAvailable(). Unchanged.
