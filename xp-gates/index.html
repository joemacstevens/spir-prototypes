Spending XP, gracefully

Today, the SPiR app gates soundscapes behind XP — but the existing BuySubscriptionPopup doesn't show the user their balance, and only reveals an "insufficient XP" message after they tap confirm. AJE-12 wants the gate to be upfront about cost, balance, and the path forward — confirm-and-spend, or hand off to the paywall.

Two visual directions below. Both demo the full flow end-to-end on a mock soundscape catalog. Click any locked tile (⚡) on either phone, walk both states, watch the telemetry panel light up. The paywall handoff deep-links to the AJE-11 prototype at paywall-revamp.vercel.app.

Placeholders: XP costs (50 / 75 / 100), balance values, and the soundscape catalog names are stand-ins. Real values come from DataConfig.featureCategories in the Unity codebase. See ASSUMPTIONS.md for the full list.

What's happening

Full-screen card, dimmed scrim, scaled-up entry. This is the closest analog to the existing BuySubscriptionPopup behaviour: it already uses PopupAndDownAnimator to scale 0→1 with Ease.OutBack. No new animator script needed for this direction.

The card body branches based on the balance check that runs before the popup is shown. Sufficient: cost row + "You have N XP" row + Confirm/Cancel. Insufficient: cost row + balance row in coral + "You need N more XP" message + "See plans" CTA + Cancel.

Annotations

1
Item-name eyebrow
Reads the soundscape's display name. Maps to whatever the caller passes (in Unity: headingText.text currently set per call site in SoundManager).
2
Cost row
Pulled from DataConfig.GetXPValueForName(name) and discounted via maxDiscount/proDiscount upstream. The popup just renders the final number.
3
Balance row (always visible)
Reads DataConfig.TotalXP. The new requirement vs today: balance is shown before confirm, not after.
4
Primary button switches based on state
Sufficient → "Confirm" (purple, calls AddandRemoveXp(-cost)). Insufficient → "See plans" (coral, calls showSubscriptionPanel(true)).
Unity Hooks (bound at refactor time)
  • Show: BuySubscriptionPopup.Show(footerCanvas) — existing
  • Animation: PopupAndDownAnimator — existing on prefab, scale 0→1 OutBack 0.5s
  • Confirm: GameManager.instance.AddandRemoveXp(-xp, "", item) @ GameManager.cs:1585
  • See plans: BuySubscriptionPopup.showSubscriptionPanel(true) @ BuySubscriptionPopup.cs:46
  • Cancel: invoke onHide action, then Hide()
  • Haptic show: Vibration.Vibrate(20) @ Vibration.cs:26
  • Haptic confirm: iOSHapticFeedback.Instance.TriggerOneShot(ImpactMedium) @ GameManager.cs:523

What's happening

Bottom sheet slides up from the phone's lower edge instead of taking over the whole screen. Less disruptive — keeps the catalog visible above. Spec'd to use a new BottomSheetAnimator using DOAnchorPos, mirroring the existing lockInTheDayPopupPanel tween at GameManager.cs:559, 569 (slide-in 1.0s linear, slide-out 0.5s linear).

The drag handle at the top is decorative for now; if Jay wants the sheet to be swipe-to-dismiss, that's a follow-up — UGUI doesn't have a native bottom-sheet gesture, so it'd need a small drag-tracker script.

Annotations

1
Drag handle (decorative)
Visual affordance only. Tappable swipe-down would be a v2 addition — not in MVP scope.
2
Two-stat layout
Cost and balance side-by-side instead of stacked. Faster to scan; mobile-native pattern from health/banking apps.
3
Catalog stays visible behind the scrim
The user can dismiss without losing context. Less modal-heavy than Variant A.
4
Same state-branching logic as A
Sufficient/insufficient detection runs before show. Different chrome, identical behaviour underneath.
